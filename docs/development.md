# Development and content

Use Node.js 24 and `npm ci`. `npm run dev` serves the lesson on localhost. `npm run check` builds and runs the tests; `npm run preview` serves the production output. Production builds require a valid tldraw key to enable the lesson, as explained in [deployment](deployment.md).

## Shared platform core

Lesson progression and pacing now live in `src/core/` under strict TypeScript checking. The family UI uses the existing compatibility entries; the local agent workspace uses the same engine for isolated rehearsals. See [platform architecture and local agent examples](platform.md) and the [domain vocabulary](../CONTEXT.md). Run `npm run typecheck` for a focused compiler check, or `npm run check` for the required full build and verification. Family screens, settings, supervision controls, entry loading and error handling now use strict TypeScript too. Edit their `.tsx` implementations; the matching `.jsx` files preserve existing import paths. Browser checking uses Vite bundler resolution, while the shared core remains independent of browser globals.

The native drawing board and crayon utility now have `.tsx` implementations too. Geometry, outline expansion, crayon paint and demonstration state live in matching `.ts` implementations; keep the `.js`/`.jsx` compatibility entries for tools and lazy recovery. `src/drawing/contracts.ts` defines authored points, separated contours, pressure gestures, palettes and native mark state. Lesson compilation, teaching-pack adaptation/registration and colouring regions now have strict `.ts` implementations too. The three authored lesson collections, all teaching-pack definitions and the catalogue use `// @ts-check` with explicit authoring contracts. All seven appearance builders and the five catalogue exporter commands are checked too; source-specific draft validators retain their runtime provenance checks. Locale registration, catalogue adaptation and the five regional dynamic-copy modules now use strict contracts too; JSON is validated when each text module loads. Type fixtures under `tests/types-browser/` verify both valid calls and rejected UI and drawing contract violations.

Sampling rejects empty/nonfinite coordinates and nonpositive spacing before calculation. The native SDK metadata reader accepts fixed hexadecimal ink and numeric style values; it does not trust the SDK metadata dictionary as an authored type. The installed SDK arrow utility has a generic registration declaration mismatch under `exactOptionalPropertyTypes`; its single local registration assertion preserves the native implementation and is covered by the actual-SDK inheritance/export test.

## Lesson authoring contracts

`src/authoring/contracts.ts` defines compiled lessons, frames, teaching text, practice windows, pack phases, registrations and colouring-region inputs. The catalogue and family `LessonView` use the same compiled `AuthoredLesson` contract. `defineLesson` accepts identities from `curriculum-scripts.json`; adding a new script also requires its observation cue and invitation to type-check. Keep the `.js` compatibility imports for offline tools and existing callers.

Keep `// @ts-check` on authored JavaScript files and include new authoring entry files in `tsconfig.browser.json`. Annotate packs with `import("./authoring/contracts.ts").TeachingPack` and give helpers explicit parameter/return types. Run `npm run typecheck` while authoring: missing narration/hints/practice windows, wrong phase names, malformed geometry and invalid pack versions should fail before a build. `tests/types-browser/authoring-contracts.ts` checks rejected calls through the real compatibility imports.

The seven appearance builders use shared `QuadraticCurve`, `CrayonGestureOptions`, `ColourRegion` and `AuthoredArt` contracts. Keep curve tables as three coordinate pairs, use palette keys in region helpers, and preserve readonly containment records and numeric phase schedules. `tests/types-browser/visual-authoring-contracts.ts` exercises their actual exports and rejects malformed authoring inputs. Authored outline styles also validate the native colour/fill/dash/size vocabulary, six-digit ink, finite widths from 0.5 to 20 and integer grain variants from 0 to 2 before rendering. Partial overrides still inherit default styles.

Types do not validate finite numbers, unique IDs, cross-file mark/phase coverage, JSON contents or reviewed wording. Runtime checks remain required. Compilation now rejects nonpositive/nonfinite mark durations and invalid frames before playback or camera setup. Pack/appearance identity and media fingerprint checks still run during `npm run check`. Compare all compiled lessons, native outline/colour marks, styles, schedules and containment data before/after authoring infrastructure changes. Keep contour-containment tests and visual review for the quality of the artwork; do not regenerate narration or previews for a type-only change.

## Localization contracts

`src/localization/contracts.ts` describes the text fields a locale may supply, its pending-review provenance, lazy text/narration loaders and regional label formatters. `src/locale-registry.ts` checks actual registrations; the `.js` entry preserves existing imports. `src/browser/language-loading.ts` uses the same compiled `AuthoredLesson` contract as authors and the family UI instead of accepting a partial timing-only lesson.

All six translated lesson modules call `createLessonLocalizer` through `src/localized-catalogue.js`. Its TypeScript implementation validates raw JSON when the lazy module opens and owns a frozen copy of allowed text fields. It checks locale/review identity, text shape and phase vocabulary before exposing the localizer; applying a lesson still checks exact stage order, phase identity and source-required nonempty fields. Extra input fields cannot replace geometry, timing, optionality, progression, music or lesson identity. English voice variants continue to share the original English lesson objects.

This shares structure, not sentences. Each locale keeps its own catalogue and dynamic grammar, and the two Spanish regions remain independent. Keep checked JavaScript annotations on the regional formatter modules and include new entry files in `tsconfig.browser.json`. `tests/types-browser/localization-contracts.ts` exercises the actual imports and rejects invalid fields, control overrides, incomplete loaders, incorrect formatter arguments and unchecked nullable lookups. `tests/localized-catalogue.test.js` covers malformed module data, source isolation and allowed-field copying for all six translated locales.

Static contracts and successful JSON parsing do not approve wording or pronunciation. Keep the [localization workflow](localization/README.md), editorial exporters, source fingerprints, recording manifests and human review requirements intact. For infrastructure-only changes, compare all localized lessons, labels, dictionaries and narration identities against the baseline; do not regenerate recordings or edit content merely to satisfy types.

## Offline export contracts

The five `scripts/export-*.mjs` catalogue commands use checked JavaScript and the shared TypeScript modules in `scripts/localization/`. `export.ts` accepts raw records as unknown data, checks complete ordered lesson/stage coverage and permitted text fields, then uses the same `createLessonLocalizer` contract as the family UI. Its output is an owned, frozen `LocalizedCatalogue`. Regional exports additionally require nonempty UI strings and sample text; reviewed Spanish/French exports derive narration keys from the existing shared helper.

Keep source-specific validation before compilation. Source hashes, phase identities, editorial status, optionality and regional wording remain separate requirements. The French geometry hash and both historical Spanish review-status forms remain supported; no exporter upgrades native-human review status. German/Italian and Dutch also validate the exact records they project after loading them. Existing CLI paths and flags are unchanged: no arguments produce JSON on stdout, while explicit write flags update local runtime files. Invalid arguments fail before reading or writing a catalogue. Imports do not execute a CLI or write files.

`writeExportFiles` validates destinations and serialized contents, then stages every file beside its destination before replacing any output. A staging failure leaves existing outputs intact and removes its temporary files. Each replacement is atomic, but a multi-file export is not a filesystem transaction: an I/O failure during replacement can leave a mixture of old and new complete files. Resolve the filesystem problem, rerun the exporter, and run the full build checks before committing. Do not run overlapping writes to the same catalogue.

`npm run typecheck` includes `tsconfig.tools.json` and the negative fixtures in `tests/types-tools/`. Node 24 type definitions are a pinned development dependency. The tools configuration also includes DOM declarations because the shared catalogue imports drawing helpers with canvas signatures; it does not add browser code to the command-line runtime. Keep raw JSON unknown until validated instead of casting it to a catalogue type. Source draft validators and media-generation scripts are not part of this strict migration.

`tests/content-export.test.mjs` exercises all six locale write paths in disposable filesystem copies and verifies unchanged output bytes. It also rejects malformed UI/lesson data, stale source hashes and failed staging without touching the repository's catalogues. Capture read-only exporter output before and after infrastructure changes; preserve wording, order, samples and review provenance exactly. Export validation never generates audio or authorizes publication.

## Regression checks

Run `npm run check` for the production build and Node tests. Install Python 3 and FFmpeg 8.x to run the audio fixture tests rather than skip them. The offline loop checks are qualified with FFmpeg 8.x: FFmpeg 6.1 produces different normalization and decoded-length results and fails the existing guards. CI uses the explicit [Ubuntu 26.04 runner](https://github.com/actions/runner-images/blob/main/README.md) and checks the FFmpeg major version; it does not relax loudness or continuity limits to accommodate another encoder. With no tldraw key, this command verifies the deliberately restricted licence-review build; it does not prove that the licensed lesson bundle renders.

Run the browser suite separately:

```bash
npx playwright install chromium firefox webkit  # once; use --with-deps on a clean Linux machine
npm run test:browser
```

Playwright is a pinned development dependency, absent from the application bundle. The suite launches this checkout on port 5186 with `--strictPort` and refuses to reuse another server. It exercises desktop Chromium, Firefox and WebKit, plus small touch viewports in Chromium and WebKit with reduced motion. It checks all nine language catalogues and real sample playback; adult setup, pause/resume, More time, Replay, settings, keyboard focus and Help music continuity; failed board/language/narration downloads; and the document visibility interruption handler. Each test uses a fresh browser context. No provider generation credentials are used.

Browser project names and viewport settings live in `config/browser-projects.json`; both Playwright and CI derive their project lists from it.

Screenshots, failure traces and the HTML report stay in ignored `output/playwright/`. Open the report with `npx playwright show-report output/playwright/report`. `.github/workflows/check.yml` runs on pull requests and main with read-only repository permission and no application secrets. Content/build/media checks run independently of five browser jobs. Each browser project owns its runner, development server, audio sink and [one Playwright worker](https://playwright.dev/docs/ci#workers); only its browser engine is installed. Matrix failure does not cancel the other projects. Artifacts are named `browser-evidence-<project>` and retained for seven days. The content job generates all localization packets and retains them for 14 days. The configured `main` protection requires the GitHub Actions `verify` check and an up-to-date pull request; see [release protection](deployment.md#release-protection-and-automatic-verification).

`node scripts/browser-ci.mjs run desktop-webkit` runs one complete CI project locally. It uses `playwright.ci.config.js`, collects the actual test inventory, runs it once and rejects missing/extra tests, skips, expected failures, retries, report errors or an empty suite. This command requires that browser's system dependencies and a working audio service. `npm run test:browser` keeps its existing two-worker local default. The `verify` job [runs with `always()`](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/collaborating-on-repositories-with-code-quality-features/troubleshooting-required-status-checks#handling-skipped-but-required-checks) and accepts only successful plan, content and aggregate browser results; failed, cancelled, missing or skipped dependencies cannot satisfy the required check. Negative tests exercise these outcomes through the same guard used by the workflow.

Recovery tests attach `recovery-lifecycle` JSON only on failure. This bounded 100-event log records visibility, focus, control clicks, audio state/errors, pause state and event-loop delays exceeding the controller's existing interruption threshold. It records no request URLs, headers or input values and sends no telemetry. It is test-only instrumentation; event-loop delay is evidence to investigate, not proof of the cause of a previous failure. The earlier intermittent WebKit narration-recovery failure was not reproduced in 20 focused attempts or the following full CI runs; no runtime fix is claimed. Keep the original assertion and zero-retry policy.

The headless CI runner starts a PulseAudio null sink so Firefox has a functioning audio output device. The browsers still fetch and decode the actual MP3s and advance their real media clocks; tests do not fake playback success. The virtual sink discards output and cannot establish perceived sound quality. Desktop runs normally use the existing sound service.

The Linux WebKit and touch-viewport checks do not establish Safari/iOS audio balance, physical-device interruption behavior, native-speaker approval or perceived recording quality. Before changing the audio backend, validate those properties on real devices. The current tldraw evaluation licence also still needs replacement before its documented expiry; neither test mode nor these changes bypass licence enforcement.

The development server and a deployed bundle have separate verification commands. After deployment, use [`npm run verify:production`](deployment.md#repeatable-production-verification) against the exact public origin and expected full commit. It does not start a local server, use provider credentials or disable deployment protection. Content and individual browser CI jobs each allow 20 minutes including setup and evidence upload; the small planning and required-gate jobs allow five minutes. The separate production verification job retains its 30-minute limit, complete five-configuration suite and release-identity checks. Individual test timeouts and assertions remain unchanged. Production verification also waits for the requested commit to become live within that job limit.

Board imports remain deferred until lesson selection. A failed import is retained by the current attempt so the error boundary can pause safely; selecting or restarting a lesson explicitly requests a fresh promise. Written instructions remain available after the adult confirms. Starting the next attempt does not automatically resume playback.

## Accessibility and reflow checks

`npm run test:accessibility` runs the focused accessibility suite; it is also included in `npm run test:browser` and production verification. The pinned `@axe-core/playwright` development dependency runs locally inside the test browser, is absent from the app bundle, and sends no page data to an external service. It checks available WCAG 2.2 A/AA rules and axe best practices across the nine language/voice options. No rules or application regions are excluded. Each scan attaches both violations and unresolved `incomplete` results; an incomplete result is a manual-review item, not a pass. See [Playwright's accessibility testing guide](https://playwright.dev/docs/accessibility-testing).

The suite checks catalogue, adult setup, lesson, Help and both settings tabs in every locale, plus the homepage, information dialogs and language picker. The existing console-error gate applies. Layout checks use 640 × 512 and 320 × 256 CSS pixels (the reflow equivalents of a 1280 × 1024 viewport at 200% and 400%), and 844 × 390 landscape. They check horizontal overflow, painted button text, actual hit targets after scrolling, and a useful minimum drawing area. The checkbox/radio target includes its associated clickable label. These checks simulate available CSS space; they do not operate a physical device's browser zoom, text-only zoom or screen reader.

Keyboard checks use Tab, Shift+Tab, Enter, Space and the settings arrow/Home/End keys, without programmatic focusing of controls. They cover page-heading focus, dialog entry/return, language and drawing selection, the adult gate, silent lesson startup, More time, Help, settings and pause/resume. Native dialogs may allow focus into browser chrome; the background page must remain inert. `Modal` closes in layout-effect cleanup while it is still attached, so WebKit releases its modal focus state; a separate passive cleanup restores a surviving opener after disabled lesson controls have been re-enabled. Keyboard verification uses a fresh context without scanner instrumentation. Existing real-audio checks separately verify narration and Help music continuity.

Accessible card names come from their visible localized content. Icon/compact controls retain explanatory names prefixed with the same translated words shown on screen. Do not replace visible words with an unrelated accessible label: that makes voice-control targeting harder. Catalogue cards size to their content, and short windows can scroll before the lesson's drawing area disappears. Settings use one scrolling dialog instead of squeezing its controls into a tiny inner panel.

Passing these checks does not certify accessibility. Review attached incomplete results and complete the [human and physical-device acceptance checklist](localization/acceptance-checklist.md), including native browser zoom/text enlargement, VoiceOver/TalkBack, actual touch targets and parent-supervised use.

## Startup performance

The first page mounts `StudioEntry`, which renders the existing homepage and parent information without importing the lesson catalogue, geometry, recording indexes or drawing SDK. Choosing a level starts the studio download while the language picker is open. Choosing a language fetches its text and narration alongside that download, validates the full released catalogue, and mounts the existing session controller only for the latest choice. Closing the picker invalidates the request; downloading alone neither authorizes narration nor creates audio players. Failed downloads can be retried in the picker. Session controls and the adult audio gate remain owned by `App`.

The homepage's small `src/lesson-directory.json` contains only authored lesson IDs and levels. It is generated, never edited as a second catalogue: run `npm run update:directory` after adding/removing lessons or moving their levels. Both the build and tests reject drift from the full catalogue. Shared stylesheet rules remain in the initial licensed entry to avoid a stylesheet round trip delaying the studio download. The licence-review entry remains separate.

Every Vite build enforces a startup JavaScript budget of **400,000 uncompressed bytes and 115,000 gzip bytes**, summed over the entry and all static shared imports. The current licensed entry is approximately 337 kB / 97 kB gzip, down from 1.10 MB / 331 kB gzip. The budget also rejects lesson data or SDK modules in that initial graph. A source-graph test exercises the licensed entry even in no-key CI without executing the SDK or bypassing its licence. Increasing a budget requires a measured reason; moving bytes into a statically imported vendor chunk does not evade it.

`startup-loading.spec.js` holds the real studio download pending, verifies that the homepage is usable and silent, cancels the choice, then verifies that an older language download cannot replace the latest selection. It runs on all five browser projects in development and production verification. Compiled recovery checks also interrupt and retry the studio chunk. These are deterministic download/behavior checks; wall-clock performance is measured separately so shared CI load does not create flaky timing thresholds.

For comparisons, use the previous release and candidate production builds served with identical gzip compression. Use fresh Chromium contexts at 390 × 844, disabled cache, 1.6 Mbps download, 750 kbps upload, 150 ms latency and 4× CPU slowdown. Measure homepage availability, image/font readiness, language selection, adult setup, board readiness and the first advancing narration clock. Repeat at least three times per language and report medians together with the complete journey; a faster homepage alone does not establish a faster lesson start. This simulation does not establish physical-device performance or perceived audio quality.

Catalogue counts come from lesson data, and teaching-pack registration rejects duplicate/mismatched identities instead of enforcing a fixed total. The synthetic growth test checks an eleventh Basic drawing and empty collections without adding unpublished lessons to the real catalogue. Localized dynamic labels must still match their source files in `research/`; count changes do not waive content, narration or release validation for future lessons.

## Content workflow

For new locales or changes to regional wording, forms of address, control labels, captions or narration, follow the [localization workflow and locale guides](localization/README.md). `npm run review:localization` extracts every released lesson/locale packet from current text, recordings and music without provider requests. Every run has a separate directory to preserve earlier reviewer annotations.

Locale resources are registered once in `src/locale-registry.js`; text and narration loaders remain lazy. `src/ui-translations.js` derives its dictionary map from that registry. React components use its `translate` function through `src/i18n.jsx`; the board failure screen uses the same pure function directly. English voice variants explicitly share source copy. Unknown locales and missing keys retain the English source text. Dictionaries are read-only, and registry tests check every locale against its actual text and voice manifests.

Latin American Spanish copy lives in `src/spanish-ui.es-419.json`, including board recovery messages. Editorial checks import this data directly, and the Spain Spanish draft records its source checksum. Keep that source linkage current when changing the dictionary. When adding a locale, register its resources together and verify normal, accessible and error labels; source-linked content and narration validation remain required.

Follow the [lesson template](../DRAWING_LESSON_TEMPLATE.md). Lesson geometry, instructions, demonstrations and prepared media must remain consistent. When drawing geometry changes, run `npm run update:previews`, review the catalogue against the native board, then run the full checks. Builds reject stale precomputed outlines.

Crayon patches are constructed inside authored contours with a safety margin from every edge. Changes to `src/crayon-regions.js` must preserve those boundaries and the resulting lesson geometry; `tests/crayon-regions.test.js` checks clearance and both contour directions, and the wider containment tests check the native ink envelopes.

Spanish reviewed text lives in `research/spanish-reviewed/`. `node scripts/export-reviewed-spanish.mjs --write-catalogue` verifies source fingerprints and updates the lazy runtime catalogue. This is an offline operation; it does not generate speech or activate another lesson. Draft and pilot material are retained for source comparisons and are not used as the runtime translation catalogue.

The release descriptor, narration index, durations and source manifest must agree. Build validation checks the precise texts, lesson coverage, content hashes and byte counts for every activated Spanish clip. Do not mark a locale or lesson ready merely because a translation file exists.

## Audio tooling

Normal builds and lessons use the committed MP3 library. Offline Python scripts in `scripts/` support prepared-media production and bounded credit accounting. Inspect each script's `--help` before running it. Generation requires separate authorization, explicit provider/model/voice choices, credentials held outside source control, and a declared budget. Do not run generation during a build or test.

Generated caches and provider receipts belong in ignored `media/`; provider credentials belong in an ignored local environment file with restricted permissions. Never prefix a provider key with `VITE_`. Public media provenance is recorded in the bundled notices and source manifests.

The complete Spain Spanish, German and Italian plans use `scripts/three-language-full.py`; Dutch uses `scripts/dutch-narration.py` with the source and review status described in [Dutch preparation](../research/dutch-draft/README.md). Both default to offline planning. Authorized runs require the existing shared checkout and exact credit cap. Dutch can record a twenty-lesson initial cohort, reconcile its proven billing, and then reuse those exact clips in the full plan.

Recording defaults to three concurrent requests. `--concurrency 8` uses eight only with the credit guard and a freshly verified Pro, Scale or Business tier. This stays below the documented Pro standard limit of ten ([provider concurrency reference](https://elevenlabs.io/docs/overview/models), checked 28 October 2026). The whole group is reserved before any POST; an unknown outcome blocks the next group and is never retried automatically. Concurrency does not change request identity, audio settings, the project cap or the protected credit reserve. To change recording mode, stop at the existing `.stop-after-batch` boundary, confirm the ledger is settled, then resume from the verified cache.

Closed-cohort reconciliation matches immutable receipts against authenticated request counts, input characters and billed credits over the entire recording interval, including across midnight. It retains evidence and the previous ledger, rejects duplicate reconciliation and preserves unmatched commitments. Technical validation and this accounting do not establish native-speaker or human listening review.

If a process interruption loses a response, ordinary generation remains blocked. Manual recovery must preserve the original receipt and request, match provider attempt counts and characters against the recorded requests, and retain the original full reservation before explicitly recording a replacement within the existing cap. Such events are retained in the ignored recovery archive and the ledger's `lostResponses` entries. Reconciliation checks their provenance and keeps their original reservations on top of the matched provider charges; it never presents missing audio as a completed receipt or retries an unknown outcome automatically.

## Application boundaries

The child draws on paper. Preserve the read-only teaching board, local adult acknowledgement, deterministic sequence, quiet practice and open exploration. Keep Pause, Replay and More time available; do not catch up after interruptions. Media completion is a prerequisite for the trusted controller, not authority delegated to an AI model.

Retain the default-on music choice and adult Begin gesture, opt-out, mute, immediate safety-interruption silence, keyboard focus and reduced-motion handling. Help preserves the music position and ducks beneath spoken hints; pauses, leaving the lesson, other dialogs and hidden tabs silence playback. Do not add capture, uploads, accounts, tracking or stored child profiles as incidental implementation changes.
